# 작업 전 필수 메뉴얼

이 문서는 이 워크스페이스에서 작업할 때 항상 먼저 확인해야 하는 기본 규칙이다.

## 1. 기존 원본 수정 규칙

1. 기존 원본 파일을 수정해야 할 때는 바로 수정하지 않는다.
2. 수정 이유, 수정 범위, 예상 영향도를 먼저 사용자에게 보고한다.
3. 사용자가 허락한 뒤에만 기존 원본을 수정한다.

## 2. 삭제 권한 규칙

1. 기존 원본의 삭제 권한은 사용자에게 있다.
2. 파일, 코드, 설정, 기능을 사용자 허락 없이 삭제하지 않는다.
3. 정리가 필요해 보여도 먼저 삭제 이유를 설명하고 승인받는다.

## 3. 실행 승인 규칙

1. 빌드, 배포, GitHub 푸시는 함부로 진행하지 않는다.
2. 반드시 사용자 승인 후에만 실행한다.
3. 실행 전에는 무엇을 왜 실행하는지 짧고 명확하게 보고한다.

## 4. 디버깅 보고 규칙

1. 디버깅 후 에러, 버그, 구조적 문제를 발견하면 먼저 사용자에게 보고한다.
2. 보고할 때는 문제점 자체와 그 문제로 인해 실제로 발생하는 현상을 함께 설명한다.
3. 수정 전에는 문제 목록과 영향 범위를 먼저 공유한다.

## 5. 작업 시작 규칙

1. 모든 작업은 이 메뉴얼을 다시 확인한 뒤 시작한다.
2. 작업 전에는 사용자의 요청을 한 줄로 정리하고, 관련 코드와 설정을 먼저 확인한다.
3. 이 메뉴얼은 항상 기본 규칙으로 적용한다.

## 6. 품질 기준 규칙

1. 기능과 디자인은 항상 고퀄리티 기준으로 구현한다.
2. 가능하면 고급 기능, 좋은 성능, 안정적인 구조를 우선한다.
3. 결과물은 대기업 퀄리티 수준을 목표로 한다.
4. 단, 기존 서비스의 패턴과 사용자 의도를 해치지 않는 범위에서 개선한다.

## 7. 보고 방식

1. 수정이 필요한 경우:
   수정 이유 -> 수정 범위 -> 예상 영향 -> 승인 요청 순서로 보고한다.
2. 문제를 발견한 경우:
   문제점 -> 발생 현상 -> 영향 범위 -> 권장 대응 순서로 보고한다.
3. 완료 보고 시:
   무엇을 했는지, 무엇을 검증했는지, 아직 남은 리스크가 있는지 분명하게 말한다.

## 8. 적용 원칙

1. 이 메뉴얼은 이 워크스페이스의 기본 작업 원칙이다.
2. 사용자가 나중에 규칙을 추가하면 이 문서를 계속 업데이트한다.
3. 상위 시스템 지침과 충돌하는 경우에는 상위 지침을 따르되, 충돌 사실을 사용자에게 알린다.
